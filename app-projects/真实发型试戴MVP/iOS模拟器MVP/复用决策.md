# 原生容器复用决策

日期：2026-08-01。关键词：`WKWebView`、`WKURLSchemeHandler`、SwiftUI、本地 HTML/ES module/WASM 资源、Simulator。

| 候选 | 许可证 / 维护 | 适配判断 | 决策 |
|---|---|---|---|
| [WebKit/WebKit](https://github.com/WebKit/WebKit) | Apple 官方 WebKit 源码；2026-08-01 有推送 | `WKURLSchemeHandler` 是本任务需要的系统能力来源，可正确给本地 WASM 返回 MIME。 | **使用系统 API**；不复制源码。 |
| [xjh093/JHURLSchemeHandler](https://github.com/xjh093/JHURLSchemeHandler) | MIT；2024-11 更新 | 可参考自定义 scheme 的最小结构，但项目维护较旧。 | **仅借鉴结构**；不引入。 |
| [gualtierofrigerio/CustomSchemeHandler](https://github.com/gualtierofrigerio/CustomSchemeHandler) | 未标明许可证；2026-07 更新 | 演示本地资源方案，但许可不明确，不能直接复用。 | **不使用**。 |
| [Lision/WKWebViewJavascriptBridge](https://github.com/Lision/WKWebViewJavascriptBridge) | MIT；2026-07 更新 | 活跃桥接库，但本项目不需要 JS/native 通信。 | **不使用**，避免依赖。 |
| [XWebView/XWebView](https://github.com/XWebView/XWebView) | Apache-2.0；2026-07 更新 | 通用封装超过本任务需求。 | **不使用**，保持 SwiftUI + WebKit 最薄容器。 |

结论：采用 Apple `WKWebView` 与 `WKURLSchemeHandler`，把本地网页资源打进 app bundle 并以 `hairtryon://` 提供，显式 MIME 覆盖 JS、WASM、model 与 PNG。无 CocoaPods、SPM、XcodeGen、Tuist 或第三方运行依赖。

## 2026-08-06 P0 修复复核

关键词：`WKWebView save image photo library swift`、`WKWebView camera iOS Swift`、`iOS simulator photo permissions XCTest`、`portrait-only orientation`。

- GitHub 精确搜索没有找到可直接替换现有 P0 流程的成熟组件；`xiongxiong/SwiftJSBridge`（MIT，2019 年停更）等候选只提供通用桥接，维护性和范围均不合适。
- Apple 官方 `WKScriptMessageHandler` 已覆盖网页到原生的最小消息通道；PhotoKit 的 `.addOnly` 授权与 `PHAssetChangeRequest` 已覆盖保存到照片。
- 竖屏由 `UISupportedInterfaceOrientations` 收敛为 `UIInterfaceOrientationPortrait`，不引入方向管理依赖。

结论：**继续直接使用系统 API，不新增第三方依赖**。必须自研的差异部分仅保留网页状态流、试戴叠加和保存反馈。
