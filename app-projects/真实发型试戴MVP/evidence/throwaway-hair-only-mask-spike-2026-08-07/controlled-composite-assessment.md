# 第二方案：生成候选 + 本地受控合成

状态：**机制 PASS，视觉质量 NO-GO。** 这是合成样本上的 throwaway 验证，不是生产发型试戴。

## 产物

- 正面/左侧输入：`controlled-output/{front,left}-before-source.png`。
- 可视标注：`{front,left}-imagegen-edit-annotation.png`；洋红是手工可编辑区，绿色是脸/耳/颈保护区，青线是 Bob 目标外轮廓。
- 二值 edit mask、脸/耳/颈保护 mask：同目录 `*-mask*.png`。

- 热图与统计：`{front,left}-controlled-difference-heatmap.png`、`controlled-results.json`。

## 严格像素门禁

本地合成以原图为底，仅在手工二值 mask 内将候选以受限羽化 alpha 混入；羽化值被二值 mask 截断，因此 mask 外仍是原图。两视图均满足：

| 视图 | 脸 | 耳 | 颈 | 合并保护区 | 二值 edit mask 外 |
|---|---:|---:|---:|---:|---:|
| 正面 | 0 / 79,896 | 0 / 9,064 | 0 / 29,040 | 0 / 110,278 | 0 / 393,885 |
| 左侧 | 0 / 79,292 | 0 / 7,992 | 0 / 30,560 | 0 / 108,706 | 0 / 383,833 |

单元格是“改变像素数 / 区域像素数”。所有保护区和二值 mask 外均为 0 差异；这证明**本地受控合成机制**有效，不证明生成候选本身保脸。

## 人工质量检查

| 项目 | 观察 | 结论 |
|---|---|---|
| 发际线 | 顶部大致连贯，但与保护脸边界的过渡只能依赖手工缓冲。 | 有条件 |
| 耳/颈遮挡 | 数值上完全保护；视觉上 Bob 与颈后残留原长发相撞。 | 失败 |
| 接缝 / 贴图感 | 正面两侧可见直切边缘；左侧靠近耳、下颌与肩部也有硬切和密度不连续。 | 失败 |
| 长发去除 / 背景补全 | edit mask 外原长发必须保留，导致下颈/肩附近残留；局部背景补全无法自然闭合。 | 失败 |
| 发量 / 发质 | 候选本身的 Bob 密度尚可，但与保留原图叠接后不再像自然生长。 | 失败（最终合成） |

## 结论与下一阻塞

**NO-GO：不要将这种手工 mask + 整图 ImageGen + 本地贴回方案当作真实发型试戴核心。** 它能机械地把脸、耳、颈锁为 0 差异，却无法解决真实发丝、耳后遮挡、颈后长发删除和背景补全边界；修补这些接缝会退化为手工图像编辑，也不能扩展到用户。

下一步必须是可许可、可在 M4 预算运行的真实 hair parsing / matting（至少 hair、face、ears、neck、background 分区）加支持显式 binary mask 的 inpainting backend；之后再用明确许可的同一真人正/左/右夹具验证。当前没有此条件，因此不集成、不宣传、不继续叠加发型。
